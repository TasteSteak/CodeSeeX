# Internationalization

The desktop client ships built-in language packs under `apps/ui/public/lang`.

## Fallback Contract

- `en_us` is the canonical fallback language.
- `zh_cn` is maintained as a complete first-party translation.
- Every built-in language pack contains the complete key schema.
- When a locale has not translated a newer string yet, that key explicitly uses the English fallback value instead of displaying a raw key or silently borrowing Simplified Chinese.
- Third-party language packs may omit keys; the client still falls back to `en_us` at runtime.

Language names in the selector remain native names supplied by the language manifest. Sorting uses the language pack identifier or manifest `sort_key`, not translated display text, so switching the current UI language does not rename or reorder unrelated language options.

## Validation

Before release:

1. Parse every JSON language pack.
2. Compare every built-in pack against the `en_us` key set.
3. Confirm no built-in pack is missing a key.
4. Confirm release notes fall back to English when a localized release entry is unavailable.
5. Keep logs and developer fallback text in English unless an explicit localized key exists.
